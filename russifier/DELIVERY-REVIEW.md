# Проверка поставки без проектора — 9 октября 2026

Версия 1.15.0 — кандидат для испытаний. BEAM Launcher и устройство не изменены. Первичная установка автозапуска и обратная процедура подготовлены по ранее проверенным механизмам, но на реальном проекторе пока не запускались.

## Установка и удаление

- Обычный INSTALL остаётся временным вариантом без автозапуска.
- INSTALL_AUTOSTART — первая установка на исходную совместимую систему. Проверяет полный комплект, модель, прошивку, оригинальные APK, ru-RU, SELinux и свободное место. Уже установленный helper или известный старый перевод требуют отдельного обновления/отката; процедура не превращает любое состояние в «чистое» автоматически.
- Существующая OEM-политика памяти сохраняется целиком вместе с правами и контекстом. Добавляется только запись helper; независимое изменение политики блокирует обратную замену. Глобальная оптимизация памяти не отключается.
- Перевод, неизменяемое поколение файлов и политика подготавливаются до включения службы. Другие службы специальных возможностей сохраняются. OEM-политика вступает в силу при следующем полном запуске Android; установщик не перезагружает устройство автоматически.
- REMOVE_AUTOSTART отменяет именно первую установку, созданную этим комплектом: выключает и удаляет helper, восстанавливает политику и состояние перевода из резервной копии, сохраняет поздние изменения пользовательских данных по существующим правилам. Это не сброс к заводским настройкам и не универсальное удаление более ранних чужих изменений.
- RECOVER_AUTOSTART возвращает состояние до прерванной установки по явно выбранному журналу. Журнал сверяется с серийным номером, fingerprint, версией и набором payload. При неизвестном APK helper, изменённой политике, скине или RRO операция останавливается.
- Backing-файлы поколений сохраняются после удаления: работающие процессы могут ещё держать старые namespaces. Автоматическая рекурсивная очистка этих файлов не добавлена.
- Новый стандартный INSTALL/ROLLBACK отказывается работать поверх активного helper: используется UPDATE_BOOT или соответствующая обратная процедура.

## Проверки и их границы

- 42 теста прошли, без пропусков: существующие проверки перевода данных, обновления и namespace, новые проверки первой установки, отказов и удаления.
- Проверены пять границ прерывания: перевод, OEM-политика, отказ PackageManager, потеря ответа после установки helper, включение службы. Журнал позволяет отменить установку, сохранив чужие службы.
- Сформированные shell-сценарии выполнены через Git Bash: реальная замена/возврат файла политики, отказ копирования, независимая правка, снятие нескольких слоёв собственных APK и остановка на неизвестном слое. Android-only команды моделируются.
- Helper versionCode=12 собран и проверен apksigner. Новый boot bundle относится к отдельному поколению 1.15.0; прежний ZIP 1.14.0 не заменяется.
- Статический аудит: SHA256 всех 22 payload совпали; параметры 159 переводов сверены с сохранёнными оригиналами, расхождений нет. В проверяемых resourceChecks нет CJK. В четырёх DEX-пакетах найдены 395 / 380 / 460 / 103 уникальные короткие CJK-строки; это кандидаты, включая служебные строки, а не число непереведённых видимых пунктов. Полный локальный список: `investigation/offline-delivery-2026-10-09/text-audit.json`, воспроизводимый сценарий: `scripts/audit_delivery.py`.
- Для проверки готового ZIP подготовлен `scripts/verify_release.py`: извлечение в путь с кириллицей и пробелами, встроенный Python, ограниченный PATH, справка семи режимов, неверный адрес через семь CMD, проверка поколения и только `adb version`. Отчёт smoke сохраняется вне архива, подключение к устройству не выполняется.

Android моделируется в тестах; это не доказательство подключения Accessibility, работы OEM memory manager или сохранения после холодного старта. Запуск встроенного Python с ограниченным PATH на текущем Windows также не заменяет испытание на чистой виртуальной машине Windows. Кандидат не публикуется как стабильный релиз.

## Следующие исследования

1. Раннее применение: текущие сохранённые результаты не нашли штатный hook из /data в просмотренных init.rc. Boot/Magisk потребуют отдельного теста и подтверждённого аварийного восстановления; патчи boot/system не включены в поставку.
2. Поставка бинарных разностей: создавать патч только к точному SHA256 оригинального APK, извлекать исходник с устройства, проверять SHA256 восстановленного APK перед применением. Такой способ не отменяет текущих ограничений подписей и системного доступа. Полные образы system/vendor и пользовательские базы не публикуются.
3. Текст: ресурсные ключи, форматные параметры и остаточные CJK/английские строки проверяются статически. Текст в DEX может быть именем протокола, логом, серверным ключом или UI; автоматическая замена всех китайских строк недопустима.

## Необходимое испытание на проекторе

Чистая первая установка → видимый перевод → новый boot_id после полного reboot → холодное включение → смена темы → удаление → ещё один reboot и отсутствие повторного применения. Отдельно обновление уже установленного прототипа и восстановление связи после прерывания. До этого кандидат не обозначается как стабильный публичный релиз.
