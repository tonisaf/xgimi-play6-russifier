# Независимые кнопки пульта — 0.6-test

Текущий модуль com.beam.remote не зависит от BEAM. Четыре кнопки 2118–2121 назначаются на приложения, медиакоманды, штатное действие или отсутствие действия. UI выполнен в стиле штатных настроек; вход добавлен в Общее. Автозапуск через KeyBridge (Accessibility), перехват через OEM Binder и foreground KeyService. Это эксперимент, проверенный только на Play 6 / v1.7.116.

## Установка

APK входит в русификатор 1.19.15 / Setup1.15. В установщике доступны отдельные установка/обновление, включение, отключение и восстановление активации. Назначения сохраняются при install -r, прежнее состояние включения сохраняется, чужие Accessibility-службы не перезаписываются. Установка добавляет только правило com.beam.remote (start=200/min=500/max=800) в /data/local/xgimi_gmui_manager/sys_pkg_adj.json с резервной копией и проверками SHA256/metadata; правило загружается после reboot. Глобальная оптимизация памяти не отключается. Откат политики применяется к записи своего пакета и сохраняет независимые изменения. См. [пользовательскую инструкцию](../russifier/REMOTE-BUTTONS.md).

## Сборка и проверки

- JDK (проверен локальный JDK 17+), Android SDK platform 34 и build-tools 34.0.0; JAVA_HOME/ANDROID_HOME задают пути. Ключ подписи и password.txt находятся в .local/boot-signing и не публикуются. Для обновления установленного пакета нужен тот же ключ. Новая независимая сборка может использовать собственный ключ с alias russifier.
- `python remote-buttons/build.py --stage` собирает подписанный dist/xgimi-remote-buttons-0.6-test.apk, проверяет подпись, добавляет APK и его метаданные в russifier. Уже существующий артефакт не перезаписывается; для нового выпуска меняйте versionName/versionCode.
- `python remote-buttons/test_registry.py` проверяет настоящий Java-учёт регистраций с имитацией потерянного ответа, частичного успеха, отказа снятия, отрицательного ответа и смерти сервера.
- `python -m unittest discover -s russifier -p test_remote_setup.py` проверяет установку, сохранение enabled-состояния, восстановление и проверку хеша.

KeyService выполняет OEM Binder-вызовы на одном рабочем потоке. Таймер 8 секунд ограничивает ожидание подключения и первой синхронизации. Просроченное поколение не запускает действия; переподключение ждёт снятия прежних регистраций. Синхронный Binder-вызов нельзя принудительно отменить: если OEM завис навсегда, UI продолжает работать, но служба ждёт возврата вызова либо завершения процесса, не создавая новые потоки/слушатели.

## Воспроизводимая сборка входа в штатные настройки

1. `python scripts/fetch_apktool.py` получает APKTool 2.10.0 из [официального выпуска](https://github.com/iBotPeaches/Apktool/releases/tag/v2.10.0); SHA256 зафиксирован в tools.json. Сеть используется только этим явным шагом.
2. Из ранее проверенного ZIP русификатора 1.19.10 возьмите payload/panel.apk (SHA256 a901619a3559e19bf62764b89816eb0d026db6fbc4cde453b54cb0cf52a97e2f).
3. `python remote-buttons/build_stock_menu.py --base ПУТЬ/panel.apk --work НОВЫЙ_КАТАЛОГ` декодирует именно этот APK и добавляет два изменения smali. JAVA_HOME задаёт JDK; --apktool может указать тот же проверенный инструмент в другом месте.
4. build-info.json записывает входной хеш, хеш инструмента, два изменённых smali и выходной хеш. Остальные ZIP-members проверяются на неизменность. Скрипт не заменяет payload и не устанавливает результат на устройство.

## Архив эксперимента 0.1

Исходники отдельного Android-приложения `com.beam.remote`. BEAM и работающий русификатор не изменены. APK не включен в основной установщик. Проверка регистрации кода 2119 вернула true, затем выполнен unregisterInterceptKey. Физические нажатия и постоянная работа ещё проверяются.

## Что готово

- Экран из четырех кнопок, расположенных как на фотографии пульта: сверху Youku/CIBN и Tencent TV, снизу iQIYI и Mango TV.
- Собственные схематические векторные значки для распознавания; это не точные оригинальные логотипы.
- Выбор установленного приложения, «Как в прошивке» и «Не выполнять действие»; назначения хранятся отдельно от BEAM, пока НЕ применяются.
- Пассивная API-проба: bindService → проверка descriptor IXgimiService → getGimiCommon (transaction 1) → проверка descriptor IGimiCommon. При обычном открытии registerInterceptKey не вызывается. Диагностический запуск --ez probe true --ez registerProbe true отдельно проверяет регистрацию кода 2119 и немедленно снимает её. Получение Binder не доказывает, что регистрация клавиши разрешена.
- Локальный диагностический результат files/probe.json и logcat с тегом BeamRemoteProbe.

## Сборка

`python remote-buttons/build.py` — JDK, Android SDK/build-tools 34.0.0, локальный ключ .local/boot-signing/key.p12 и password.txt. Ключи не входят в Git. При необходимости пути JAVA_HOME/ANDROID_HOME задаются окружением. Выход: dist/beam-remote-buttons-0.1-probe.apk + SHA256. Новый пакет, не обновление BEAM или штатных настроек.

## Проверка на проекторе

1. Сохранить текущие назначения BEAM. Установить диагностический APK через adb install -r.
2. Запустить com.beam.remote/.RemoteActivity (для автоматической пробы передать --ez probe true).
3. Проверить UI, навигацию пультом и выбор приложения; получить диагностический результат. Убедиться, что все существующие кнопки работают как прежде.
4. Только после успешной пробы подготовить отдельную экспериментальную регистрацию одного подтвержденного кода клавиши с явным выключателем и снятием регистрации. Коды двух оставшихся кнопок определить на реальном пульте, не выводить их из названий приложений.
5. Проверить OEM разрешения, конкуренцию с BEAM/стоковым обработчиком, отсутствие двойного запуска, восстановление после перезапуска службы и полного reboot. Проверить возврат к стоковому действию.
6. Добавить пункт «Кнопки пульта» в штатные настройки: структура меню/Cell и собственное действие запуска RemoteActivity. Сначала нужен согласованный маршрут меню и безопасный fallback, если модуль отсутствует. Проверить dpad-фокус, прокрутку и сохранность остальных пунктов. Это требует нативного патча, одним переводом RRO пункт не добавить.
7. После проверки включить модуль в поставку с отдельной опцией. Отделение/удаление функции из BEAM делать отдельно, чтобы не поломать действующие назначения.

## Откат прототипа

`adb uninstall com.beam.remote` удаляет только этот новый пакет и его черновики. Постоянные назначения прототип не меняет; при диагностическом флаге кратковременно регистрирует 2119 и снимает регистрацию. Root, Accessibility и постоянный foreground-сервис на данном этапе не включаются.
