# Автовосстановление после перезагрузки: эксперимент 8 октября 2026

Устройство: XGIMI Play 6, Android 11, v1.7.116. Основной установщик остаётся версии 1.13.0; эксперимент ещё не включён в его ZIP и штатный откат.

## Что установлено

Отдельное приложение `com.beam.russifier.boot` с обычной подписью разработчика. Нет INTERNET permission, зависимости от BEAM Launcher, Magisk или записи в system/vendor. Приложение запускает только фиксированный скрипт, сверяя его SHA256 и fingerprint. Скрипт заранее проверяет оригинальные APK, три native-патча, 14 RRO и скин; затем восстанавливает idmap, включает RRO и bind-mount в пространстве zygote. Геометрия, яркость и выбор звукового выхода не меняются.

Файлы эксперимента расположены в root-owned `/data/local/beam-russifier-boot`, каталог 0755, файлы 0644. Root используется кратковременно через штатную диагностическую службу OEM; отдельного root-демона нет. Корректная работа зависит от текущей прошивки и SELinux Permissive.

## Почему обычный BOOT_COMPLETED не работал

Журнал: `third part process dont start for broadcast: 10035/com.beam.russifier.boot`. В `ProcessList.startProcessLocked` OEM проверяет `persist.xgimi.mem_optimise.enable`, значение по умолчанию `true`; при включённой оптимизации отказывает в старте несистемного приложения для broadcast. Отказ выглядит как `process is bad`, хотя приложение не падало.

Исходное значение свойства было пустой строкой, то есть действовал default=true. Временное значение `false` позволило запустить BootReceiver.

## Проверка

Первый чистый reboot с исходным параметром: BootReceiver не запущен, старый completion token; ручное восстановление отдельно работало.

JobScheduler: сохранённое периодическое задание зарегистрировалось и пережило reboot; вызов JobService смог восстановить патчи в текущем сеансе. После reboot Android назначил следующую попытку через 15 минут, окно 15–30 минут. Ожидание отменено по выбору пользователя; автоматическое выполнение задания после reboot НЕ доказано. Не выдавать этот вариант за готовый быстрый автозапуск.

Первый reboot с временным `mem_optimise.enable=false`: новый kernel boot_id, новый completion token, `restore=ok`, три runtime SHA256 совпали с манифестом. Восстановление обнаружено примерно через 96 секунд после команды; компьютер только читал журнал, не применял патчи. Снимок подтвердил русскую дату, яркость, Bluetooth и кнопку «Звук». OEM завершил helper после перезапуска SystemUI до сохранения UI-статуса; лишний перезапуск SystemUI удалён из boot-скрипта. Также добавлены timeout команд и очистка диагностических свойств в root trap.

## Границы и следующий шаг

Постоянный быстрый автозапуск требует оставить OEM-оптимизацию выключенной. Это влияет на фоновые ограничения других приложений и может увеличить расход RAM; это отдельный выбор пользователя. Временное изменение нужно вернуть после проверки. Для распространения требуется интеграция в INSTALL/ROLLBACK: снимок исходного свойства, отключение helper перед откатом, versioned immutable backing files, сохранение/удаление только своих файлов. APK версии 1.14.0 здесь является прототипом, не релизом.

Не удалять backing APK, пока они используются bind-mount. Перед любым прежним ROLLBACK остановить тестовый автозапуск: `adb shell pm disable-user --user 0 com.beam.russifier.boot`, отменить JobScheduler #1400. Основной ZIP 1.13.0 сам этот helper не удаляет.

Подпись хранится локально в `.local/boot-signing`; ключ и пароль не публикуются. Для сборки: сначала `generate_restore.py`, затем `build_app.py` (локальный SDK/JDK, фиксированные пути). Оригинальные APK, логи с данными пользователя, снимки и бинарные артефакты не входят в Git.
